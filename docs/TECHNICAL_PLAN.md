# Технический план Пружинок

## 1. Границы первого релиза

Рабочий прототип — 14 игр на одной форме вопроса, единый реестр из 2141 активной записи, RU/EN, локальный прогресс и собственная визуальная система. Первый выпуск — тот же набор плюс озвучка чисел 0–999 и речевая проверка записей носителем.

Приложение статически разворачивается, аккаунта и серверного API нет. Генерация озвучки — отдельная редакционно-производственная операция; ключи и пути к моделям в клиентскую сборку не попадают. Экран хранится в состоянии React, URL и History API не используются, для аппаратной кнопки «Назад» на Android ставится обработчик `@capacitor/app`.

## 2. Стек и основания

- Node.js 22+, npm.
- React + TypeScript + Vite для клиента и статической сборки.
- `i18next` + `react-i18next` с первого этапа, стартовые ресурсы `ru` и `en`.
- CSS с собственными токенами; визуальная система берётся из Arahet и не задаётся готовым UI-китом.
- IndexedDB для прогресса, карточек, журнала ответов и предпочтений; `localStorage` — только для языка интерфейса.
- Vitest для чистой доменной логики и движков игр; Playwright для ключевых браузерных сценариев.
- Capacitor 6 — офлайн-APK, добавляется в конце.

Доменные правила и контент не помещаются в компоненты React. UI получает готовый вопрос и результат домена, а не решает сам, что считать правильным ответом.

## 3. Структура репозитория

```text
src/app/App.tsx                  оболочка, экраны, навигация, загрузка и сохранение
src/games/<режим>/engine.ts      чистый движок режима, без React
src/games/<режим>/GameView.tsx   вид поверх движка
src/domain/                      прогресс, SM-2, сессия раунда, награда, статистика
src/content/                     типы, реестр записей, колоды, манифест озвучки
src/services/                    хранилище прогресса, плеер озвучки
src/i18n/                        словари ru/en и инициализация
src/fonts.css, src/styles.css    локальные шрифты, токены и стили
scripts/                         импорт словаря, валидаторы, аудиоконвейер
tests/                           сценарии Playwright
docs/                            план продукта, этот план, игры, аудио
```

Каждый режим игры разделён на движок и вид. Движок — чистые функции с внеднёнными `now` и генератором случайных чисел, поэтому он тестируется без DOM и воспроизводится по `seed`.

## 4. Слияние словарей

`scripts/import-lexicon.ts` — повторяемый скрипт, читающий реестр Arahet и `assets/content/words.seed.json` проекта `aybuch`. Он ничего не правит в источниках.

| Поле | Arahet | `aybuch` |
| --- | --- | --- |
| `hy`, `translit` | есть | есть |
| `ipa`, `reading` | есть у первых слов | практически нет |
| переводы | один `meaning{ru,en}` | массивы `translations.ru[1..3]`, `en` |
| `themeId`, `pos`, `level` | нет | есть |
| идентификатор | `word-arev` | `w001` |
| файл озвучки | `<id>-<voice>.m4a` | `<id>_<voice>.m4a` |

**Правило дедупа.** Если армянский текст записи `aybuch` совпадает с записью Arahet, побеждает Arahet: у него есть IPA, подсказка чтения и пройденная редакторская проверка. Запись `aybuch` получает `mergedInto` и **не попадает ни в одну колоду, игру или выборку**. Её озвучка не копируется.

**Инварианты, которые проверяет валидатор:**

- `id` уникален глобально по всем 2188 импортированным записям;
- `hy` уникален **только среди активных** записей — совпадение у помеченной записи обязательно и ожидаемо;
- `mergedInto` всегда указывает на существующую активную запись;
- каждая запись `hy` содержит армянский кодпоинт;
- `translations.ru` и `translations.en` — непустой массив от 1 до 3 строк, `en` не равен `ru` там, где это содержательно.

**Числа.** 1000 значений 0–999 становятся полноценными записями с идентификаторами `num-000`…`num-999`: ведущие нули дают совпадение лексикографического и числового порядка. Текст берётся вызовом `numberToArmenian` из перенесённого `numbers/core.ts`, поэтому текст вопроса и текст озвучки не могут разойтись. Без этого числа не попадали бы в `items` и `cards`, и статистика по ним обрывалась бы.

## 5. Колоды

Колоды **вычисляются** из реестра, а не хранятся списками. Тематическая колода — фильтр по `themeId`, уровневая — по `level`, «Все подряд» — весь активный пул. Хранить списки идентификаторов означало бы второй источник правды, который разойдётся при любом изменении словаря.

Тема `basics` (1197 записей) исключена из тематических колод: это резервуар всех поздних дозагрузок, а не тема. Порядок идентификаторов внутри словаря педагогическим не является, поэтому единственная надёжная ось упорядочивания — уровень.

## 6. Прогресс

```text
GameProgress {
  schemaVersion: 1
  contentVersion: number
  updatedAt: number
  preferences: { fontScale, voice, unreviewedAudio, translitHints, timerOn, timerSeconds }
  items:   Record<itemId, { introducedAt?, correct, wrong, bestMs, lastPlayedAt, streak, mastery }>
  cards:   SrsState[]
  reviews: ReviewEntry[]                          // кольцевой буфер
  decks:   Record<deckId, { plays, bestStars, lastPlayedAt }>
  records: Record<gameId, { best, bestAt }>
  daily:   Record<gameId, { date, score, stars }>
  streak:  StreakState
}
```

**Верхние границы.** Эти ограничения обязательны, иначе объект растёт неограниченно и строгий декодер обязан принимать бесконечное множество форм:

- `daily` — **одна запись на игру**, перезаписывается при смене локальной даты. Ключ вида `gameId:YYYY-MM-DD` дал бы 14 записей в день и 5110 за год.
- `reviews` — кольцевой буфер на 2000 записей; при записи отбрасываются самые старые.
- `records` — только для соревновательных игр. У карточек SM-2 счёта нет, поэтому записей 13, а не 14.

**Строгий декодер.** Неизвестный ключ, неизвестный тип или поле вне допустимого набора — исключение при чтении, а не тихое игнорирование. `assertAllowedKeys` переносится из Arahet.

**Отношение к `contentVersion`.** В Arahet состояние с чужим `contentVersion` отвергается целиком, и это правильно для уроков: учебный маршрут при смене содержимого действительно меняется. Здесь ценность приложения — в накопленной статистике по 2141 элементу, и обнулять её при каждом обновлении словаря нельзя. Поэтому `contentVersion` поднимается только на ломающих изменениях, а декодер **терпит неизвестные `itemId` и отсекает их при чтении**. Прецедент есть в обоих соседних проектах: Arahet фильтрует карточки, чей элемент исчез из реестра, `aybuch` дополняет сид только недостающими идентификаторами и не трогает существующие карточки.

**Настройки** хранятся в `preferences` необязательными полями, поэтому добавление новой настройки не требует повышения `schemaVersion`.

**Хранилище.** `armgames-progress` версии 1, отдельная база. Запись сериализована очередью, вкладка с меньшим `updatedAt` не может затереть более новую запись, состояние повторно декодируется перед записью, ошибки сохранения показываются ученику. Механизм переносится из `Arahet/src/services/progressStore.ts`.

## 7. SRS

Планировщик — SM-2 из соседнего проекта, переносится дословно вместе с тестами:

- `Grade` 0–3: «не вспомнил / с трудом / вспомнил / легко»;
- коэффициент лёгкости в границах 1.3–3.0;
- провал сбрасывает интервал, счётчик `lapses` растёт, повтор через 10 минут;
- зрелость карточки: `new` → `learning` → `young` (интервал меньше 21 дня) → `mature`;
- порог «трудного слова»: три провала.

Сессия повторения — пачка ограниченного размера, смысл карточки скрыт до оценки. Оценка ученика попадает в `items` и в `reviews` с временем ответа.

## 8. Две семьи игр

Полная спецификация — в [GAMES.md](GAMES.md). Здесь только устройство.

**Экранные** (`pairs`, `bingo`, `srs`) имеют собственное поле и собственный жизненный цикл: счёт ходов, отметки на доске, оценка карточки.

**Раундовые** (11 штук) используют одну форму вопроса и общий цикл раунда: таймер, пять жизней, звёзды. Новая игра — одна функция-генератор плюс вид, а не новая архитектура.

**Таймер** отсчитывает время только в раундовых играх и обрывает раунд по достижении. Он держит не счётчик, а **абсолютный `endsAt`**: браузер душит таймеры в фоновой вкладке до интервала в минуту и дольше, и раунд на 60 секунд иначе длится неограниченно долго. У экранных игр время — только статистика в финале.

**Жизни** — пять, только в раундовых играх и в `bingo`, никогда не сохраняются и не переносятся между играми. У `pairs` ошибок нет по построению, у `srs` оценку даёт ученик.

**Звёзды** считаются по семействам, одним правилом на все игры пользоваться нельзя:

| Семейство | Правило |
| --- | --- |
| Раундовые | минимум из «за ошибки» и «за долю верных» |
| `bingo` | по числу ошибок |
| `pairs` | по числу лишних ходов относительно числа пар |
| `srs` | звёзд нет, в финале сводка по четырём оценкам |

Взять минимум из двух правил в раундовых играх обязательно: раунд на 60 секунд без единой ошибки, но с 3 верными из 20, не должен давать три звезды.

## 9. Отклонённые игры соседнего проекта

Из 13 игр хаба `aybuch` самостоятельными являются восемь: остальные пять — один и тот же вопрос с вариантами под разными именами, иконками и таймерами. Это не переносится.

| Игра | Причина |
| --- | --- |
| `guess`, `sprint`, `daily` | тот же вопрос с вариантами; таймер и запись за день — параметры сессии, а не механика |
| `duel` | тот же вопрос с вариантами плюс маскот, которого в первом выпуске нет |
| `odd-one-out` | объявлена «что лишнее», но сводится к обычному вопросу с вариантами; заменена игрой «Чужой» с разбором темы |
| `chain` | «выбери слово на эту букву» вырождается в угадывание, когда в группе одно слово; заменена игрой «Допиши» |
| `reverse` | дефект: правильный ответ всегда первый вариант |
| `catch-letter` | дефект: варианты берутся из начала списка без перемешивания, их может оказаться меньше четырёх |
| `constructor` | токены собираются из транслитерации, то есть тренируется латиница, а не слово |

## 10. Локализация

Словари `ru` и `en` с одинаковым набором ключей; расхождение останавливает сборку. Армянский текст хранится один раз, рядом — оба перевода. `<title>` и `meta description` берутся из ключей `meta` и следуют за языком интерфейса, поэтому статический `index.html` содержит только начальные значения.

Названия игр, названия колод и подписи режимов локализованы; тексты игр берутся из словаря и не дублируются в интерфейсе.

## 11. Визуальная система

`styles.css` переносится из Arahet с механическим переименованием: `--rust` → `--accent` (72 ссылки), `--rust-deep` → `--accent-deep` (8 ссылок), две зашитые значения заменяются токенами ошибки и верного ответа. Объявленный, но не используемый `--sage` удаляется. Остальное сохраняется: сетка, шапка, надзаголовки, моноширинные подписи, точки прогресса, брейкпоинты 800 и 560, `prefers-reduced-motion`, все размеры через `var(--font-scale)`.

Акцент — охра `#b5822a`, глубокий `#8a5f17`, ошибка `#a33f3f`, верно `#42664b`, глиф вордмарка `Թ`. Награда рисуется SVG: эмодзи разрушают типографику.

Анимация ограничена `transform` и `opacity`, не более двух зацикленных циклов на экран. Правило перенесено из соседнего проекта, где оно защищало производительность на слабом устройстве.

## 12. Аудио

Плеер и манифест переносятся из Arahet: один элемент воспроизведения, остановка предыдущей записи, два голоса, `reviewed: false` до речевой проверки, кнопка прослушивания **прячется**, если запись недоступна. Подробности, лицензия модели и батч чисел — в [AUDIO.md](AUDIO.md).

## 13. Проверки

| Команда | Что ловит |
| --- | --- |
| `npm run typecheck` | ошибки типов, включая типизацию ключей локализации |
| `npm test` | движки игр, домен, хранилище, валидаторы |
| `npm run validate:content` | уникальность идентификаторов, дедуп, темы, переводы, озвучка, доступность режимов, паритет ключей |
| `npm run validate:audio` | совпадение текста манифеста и данных, наличие обоих голосов, безопасные имена |
| `npm run build` | валидация, затем сборка; `RELEASE_AUDIO=1` запрещает публиковать непроверенные записи |
| `npm run test:e2e` | главная, колода, пары, финал, сохранение после перезагрузки, работа с клавиатуры |

Движки игр пишутся так, что один и тот же `seed` даёт одну и ту же последовательность вопросов: тест на детерминизм обязателен, иначе падение не воспроизводится.

## 15. Логическая схема коммитов

- `docs: record product and technical plans for the games app`
- `chore: bootstrap the games app shell and ochre accent`
- `feat: merge both Armenian dictionaries into one lexicon`
- `feat: validate lexicon, decks and mode eligibility`
- `feat: add local progress, sm-2 scheduling and review log`
- `feat: add pair matching, audio bingo and sm-2 cards`
- `feat: add the eleven round games`
- `feat: generate spoken numerals from zero to nine hundred ninety-nine`
- `build: package the games app for android`

Коммитить после прохождения относящихся к блоку проверок. Перед отправкой просматривать состояние, разницу и историю. Выгрузка озвучки не добавляется отдельным большим коммитом без явного решения: файлы уже копируются на этапе 2 и 10, и их объём нужно видеть в истории до отправки.
